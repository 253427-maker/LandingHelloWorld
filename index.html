Hoy diseñé una card de producto y este es el HTML

Una tarjeta sencilla con imagen, nombre, descripción, precio y botón. Cuento cómo la estructuré y por qué usé etiquetas semánticas.

La consigna era maquetar un componente reutilizable. Elegí una card de producto porque reúne casi todo lo básico: imagen, jerarquía de texto, una acción y espaciado consistente.

El HTML

<article class="card">
  <img src="producto.jpg" alt="Taza de cerámica color arena" class="card__img">
  <div class="card__body">
    <h3 class="card__title">Taza de cerámica</h3>
    <p class="card__text">Hecha a mano, 300 ml.</p>
    <div class="card__footer">
      <span class="card__price">$180</span>
      <button class="card__btn">Agregar</button>
    </div>
  </div>
</article>

El CSS que sostiene el diseño

.card { max-width: 280px; border-radius: 16px; overflow: hidden; background: #f6f3e8; }
.card__img { width: 100%; aspect-ratio: 4 / 3; object-fit: cover; display: block; }
.card__body { display: grid; gap: 8px; padding: 16px; }
.card__footer { display: flex; justify-content: space-between; align-items: center; }

Lo que me llevo

  • Usar article hace que la card tenga sentido por sí sola, incluso fuera de una lista.
  • aspect-ratio reserva el espacio de la imagen y evita saltos al cargar.
  • gap en lugar de márgenes sueltos mantiene el ritmo vertical parejo.

3 errores comunes de espaciado al maquetar y cómo solucionarlos

Márgenes que se pegan, medidas al azar y paddings que no respiran en móvil. Tres hábitos que corregí esta semana.

Mientras revisaba mis propias maquetas encontré tres patrones que hacían que todo se viera un poco desordenado sin saber bien por qué.

1. Usar márgenes para separar todo

Terminas con espacio extra debajo del último elemento y márgenes que se fusionan de forma inesperada. Solución: dejar que el contenedor reparta el espacio con gap.

.stack { display: grid; gap: 16px; }

2. Medidas arbitrarias

13px aquí, 17px allá. Solución: definir una escala de espaciado y usarla siempre.

:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 16px;
  --space-4: 24px;
  --space-5: 40px;
}

3. Mismo espaciado en pantalla grande y en móvil

Un padding de 80px se ve elegante en escritorio y se come la pantalla en un teléfono. Solución: una medida fluida con clamp().

.section { padding-block: clamp(32px, 6vw, 80px); }

Pilas y colas: una imagen mental para no confundirlas

Una pila es una torre de platos; una cola es la fila de la tienda. Con esa imagen, el orden de salida deja de ser un misterio.

Las dos estructuras guardan elementos en orden, pero se diferencian en cuál sale primero.

  • Pila (stack): el último en entrar es el primero en salir, LIFO. Como una torre de platos: tomas el de arriba.
  • Cola (queue): el primero en entrar es el primero en salir, FIFO. Como la fila de la tienda.

Probándolo con un arreglo en JavaScript

const pila = [];
pila.push("a"); pila.push("b"); pila.push("c");
pila.pop();    // "c"  (el último que entró)

const cola = [];
cola.push("a"); cola.push("b"); cola.push("c");
cola.shift();  // "a"  (el primero que entró)

Nota para mí: en listas muy grandes, quitar elementos del inicio con shift() puede ser costoso. Más adelante en la materia veremos cómo implementar una cola de forma más eficiente.

Análisis y diseño de software

De una idea a historias de usuario

Convertí la idea de esta bitácora en historias de usuario con criterios de aceptación. Escribir qué debe poder hacer alguien ordena todo lo demás.

Una historia de usuario describe una necesidad desde la perspectiva de quien usa el producto. La fórmula que usamos en clase es:

Como [rol], quiero [acción] para [beneficio].

Ejemplo con esta página

Historia: Como visitante, quiero filtrar las entradas por materia para encontrar rápido lo que busco.

Criterios de aceptación:

  • Existe un filtro por cada materia y una opción para ver todas.
  • Al elegir una materia, solo se muestran sus entradas.
  • El filtro activo se distingue visualmente de los demás.

Lo que más me gustó: los criterios de aceptación funcionan como una lista para saber cuándo algo está terminado.

Pantallas pensadas para el pulgar

Diseñar para móvil no es encoger una web. Cambia el tamaño de los botones, la distancia entre ellos y dónde ponemos las acciones principales.

Al dibujar mis primeras pantallas me di cuenta de que un botón perfecto con el cursor puede ser imposible de tocar con el dedo.

  • Las guías de diseño recomiendan áreas táctiles de al menos 44 puntos en iOS y 48 dp en Android.
  • Las acciones principales se alcanzan mejor en la parte baja de la pantalla, donde llega el pulgar.
  • Dejar espacio entre elementos táctiles reduce los toques equivocados.

Descubrimientos de la semana

Cosas pequeñas que no sabía el lunes y que ya uso el viernes.

Emmet en Visual Studio Code

Escribir ! y pulsar Tab genera la estructura base de un HTML completo. También sirve para cosas como ul>li*4, que crea una lista de cuatro elementos.

Seleccionar la siguiente coincidencia

Con Ctrl + D se selecciona la siguiente aparición de una palabra, y se pueden editar todas a la vez. Ideal para renombrar una clase en varios lugares.
